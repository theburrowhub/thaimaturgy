# thAImaturgy Modern Web App Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Convert thAImaturgy from a desktop-first Fyne app into a modern browser-based DM console that preserves the existing engine, adventure modules, session state, oracle, editor concepts, images, dice, and Telegram hosting.

**Architecture:** Keep the proven Go core (`internal/domain`, `internal/engine`, `internal/storage`, `internal/providers`, `internal/tgbot`) and add a thin HTTP/WebSocket layer plus a modern static frontend. The best version is not a marketing website and not just a prettier port of the Fyne UI: it is a **Command / Inspect** product surface for a Dungeon Master running a live session, with secondary **Operate** surfaces for library/import/settings and module authoring.

**Tech Stack:** Go stdlib `net/http`, existing Go core packages, embedded static assets via `embed`, vanilla TypeScript or plain ES modules for the frontend, CSS custom properties, Playwright/browser smoke tests where available, existing `go test ./... -race` for core validation.

---

## Product diagnosis

### What the app is for

thAImaturgy is a tabletop RPG assistant for a human Dungeon Master.

It does five jobs:

1. **Loads authored adventure modules** (`.tar.gz` containing `adventure.json` plus maps/art).
2. **Lets the DM inspect canon quickly**: zones, rooms, NPCs, events, items, tables, lore, images.
3. **Runs a grounded oracle**: the DM asks questions and the model answers using module context and tools.
4. **Tracks live session state**: current location, notes, flags, triggered events, party, timeline and conversation.
5. **Can run Virtual DM / multiplayer**: party characters, group turns, Telegram hosting.

### Best version of the product

The strongest version is a **browser DM cockpit**:

- left: searchable adventure map/tree and quick filters;
- center: live oracle/chat/command stream;
- right: selected scene/NPC/detail inspector with read-aloud, DM notes, image/map, actions;
- bottom or command palette: dice, slash commands, save, mode, Telegram host;
- library/settings/import/editor as separate focused screens, not crammed into the play view.

This should feel closer to a beautiful DM control room than a generic web dashboard. Use the visual posture from `https://aprior.es/dd/torre-estrellas/`: dark starlit shell, warm readable paper cards, strong section anchors, sapphire/gold accents, dramatic but practical density.

### Surface choice

Primary surface: **Command / Inspect**.

Reason: the DM is not browsing a marketing page; they are driving a live session and drilling into one object at a time. Speed, orientation, keyboard access, glanceable state and readable details matter more than decorative cards.

Secondary surfaces:

- **Explore**: library and adventure browser.
- **Configure**: settings, provider credentials, Telegram host setup, module import.
- **Operate**: running session actions, dice, save, mode, Telegram.

## Design direction

### Accepted design reference

Tony supplied the target visual direction in:

- `.hermes/designs/dm-oracle-moderno.html`

Treat this HTML as the canonical design reference for the first web implementation. The older idea of warm parchment panels should be dropped for the web MVP. The chosen design is darker, cleaner and more product-like: a compact DM cockpit with muted dark panels, gold action emphasis, arcane cyan activity/focus, Sora/Spectral/JetBrains Mono typography, and a persistent three-column command layout.

### Visual system from the supplied mockup

Use these tokens as the starting CSS custom properties:

- `--bg: #0d1017` — main app background.
- `--panel: #151923` — sidebar/detail/header panels.
- `--panel-2: #1a1f2c` — elevated controls, cards and hover states.
- `--line: rgba(255,255,255,.07)` — subtle dividers.
- `--line-strong: rgba(255,255,255,.13)` — control borders.
- `--text: #e9e9f0` — primary text.
- `--muted: #8b92a6` — secondary text.
- `--faint: #5d6478` — tertiary metadata.
- `--gold: #e2b25c` — primary/action/read-aloud accent.
- `--gold-soft: rgba(226,178,92,.14)` — selected states and gold panels.
- `--arcane: #7ee0d2` — oracle/focus/live-state accent.
- `--arcane-soft: rgba(126,224,210,.10)` — oracle bubble background.
- `--danger: #e0705c` — destructive/pinned danger state.
- `--radius: 12px`, `--radius-sm: 8px`.

Typography:

- Use `Sora` for interface controls and headings.
- Use `Spectral` for read-aloud prose and quoted/adventure text.
- Use `JetBrains Mono` for timestamps, command hints, slugs, dice rolls and IDs.
- If remote Google Fonts are not acceptable for offline builds, bundle/self-host these fonts or define a fallback stack with the same roles.

Composition:

- Primary surface remains **Command / Inspect**.
- Preserve the supplied 3-column cockpit: `264px | 1fr | 340px` on desktop.
- Preserve top bar rhythm: brand/eyebrow, breadcrumb/current location, action cluster, mode pill.
- Preserve left sidebar split: adventure tree above, session timeline below.
- Preserve center: oracle transcript + composer anchored at bottom.
- Preserve right: detail inspector with move/action button, scene title, read-aloud card, DM notes, exits/links.
- Responsive behavior follows the mockup: hide detail under ~1100px and sidebar under ~760px, but later add mobile tabs rather than making content unreachable.

Slop audit of supplied design:

- Score: **1/10**.
- Only minor risk: limited mobile behavior because side panels hide rather than become accessible tabs.
- No wrong surface, no hero stack, no generic feature grid, no fake metrics, no glassmorphism, no tech-gradient sludge.

### Core screens

1. **Library**
   - Hero strip with product name and quick actions.
   - Adventure cards/list with resume, edit, delete, metadata and recent session.
   - Import module drag/drop.
   - Settings access.

2. **Session cockpit**
   - Top command bar: adventure title, mode, save status, provider, Telegram status, dice, search.
   - Left pane: adventure outline with search and filters (`Rooms`, `NPCs`, `Events`, `Items`, `Tables`).
   - Center pane: oracle transcript + command input.
   - Right pane: detail inspector with tabs/sections: `Read aloud`, `DM notes`, `Actions`, `Image`, `Links`.
   - Bottom responsive rail for small screens.

3. **Detail inspector**
   - Read-aloud block clearly separated and copyable.
   - DM notes readable but visually distinct.
   - Entity actions: go to room, mark NPC met, trigger event, roll table, open image.
   - Related links as chips, not long text lists.

4. **Virtual DM mode**
   - Hide spoiler-heavy adventure browser from player-facing flow.
   - Show party sheet, round actions, Telegram host state.
   - Center transcript becomes narration/control surface.

5. **Settings/import/editor**
   - Progressive configuration: provider, model, language, Telegram, TTS.
   - Import module flow with validation feedback.
   - Editor can be phase 2: start by linking to existing module authoring functions/API.

## Risks and tradeoffs

### Fyne vs web duplication

Risk: maintaining two UIs doubles work.

Recommendation: treat web as the future primary UI and keep Fyne stable but stop adding major UI-only features there. Shared logic must stay in `internal/`.

### Secrets in browser

Risk: provider keys or Telegram token leaking through config endpoints.

Mitigation: redacted DTOs only; write-only secret updates; tests assert secrets never appear in JSON.

### Long oracle turns

Risk: HTTP request timeouts and bad UX.

Mitigation: SSE/WebSocket event model and cancellable context.

### Local data exposure

Risk: serving local adventure/session data on a network interface.

Mitigation: bind to `127.0.0.1` by default; require explicit `--addr 0.0.0.0:...`; later add auth if deployed remotely.

### Editor scope creep

Risk: rebuilding the whole editor delays core session value.

Mitigation: editor is phase 2 after cockpit MVP.
